# AI 原生個人分身系統 — 完整情境說明

> 這份文件是這次專案啟動時提供給 Claude Cowork 的完整背景說明，原封不動保留下來，方便之後回顧或再次交給其他工具/協作者當 context。

## 一、專案背景

Riku 正在朝「AI 原生工作者」的方向轉型，最終目標是要幫公司（BCI Group）打造 AI 原生系統，因此先從自己開始——把自己的判斷邏輯外顯成規則，讓 AI 代理人（Agent）代替他重複處理性工作，再逐步擴展成多代理人和諧系統。

長期目標是把「工作」跟「個人」的多個 Agent 都整合進同一套系統裡管理，包括：

- 工作／公司範疇：溝通 Agent（信件與訊息分類）、未來的財務 Agent（對應公司的 bci-finance 專案）
- 個人範疇：個人股票自動交易代理（尚未開發，未來要納入同一套系統）

系統的世界觀限制：不管在多大程度上、資料歸屬上，「個人」與「公司」都要能明確區分，不能混在一起。

## 二、目前已經定案的內容

### 1. 溝通 Agent 分類規則（已完成 v1，可直接沿用）

處理範圍：Gmail 信件 ＋ Google Chat 訊息。核心規則：

- 廣告／宣傳 → 標記已讀（略過）
- 訂閱發票類別 → 已讀＋加星號＋列待辦
- 工作平台自動通知、開發工具通知（Vercel/Supabase/GitHub）、財務帳務通知 → 未已讀/加星，但通知內容摘要
- 開發工具通知的例外：涉及專案問題或帳號權限變更（如新增令牌）→ 標記「⚠ 需要手動讀取」
- 帳號安全通知 → 略過（已標記已讀），異常才通知
- 內部行政通知、會議邀請 → 已讀即可
- 即時訊息（1 對 1）→ 3 小時未回提醒一次
- 聊天室資訊 → 依「重要聊天室名單」（使用者自行定期手動更新）判斷
- 前置規則：任何非中文內容，一律先完整翻譯成繁體中文，才進入分類判斷

### 2. 技術方向

- 前端：Next.js on Vercel + React Flow（節點圖）
- 資料庫／即時同步：Supabase（Postgres + Realtime）
- Agent 邏輯層：Vercel Serverless Functions + Claude API
- 版本控制：GitHub

### 3. 儀表板資訊架構（六大區塊）

1. 代理狀態對應（名稱、狀態、目前任務）
2. 待核准佇列（需要人工判斷的項目）
3. 異常提示（錯誤/例外，明顯標記顏色）
4. 處理記錄／歷史記錄
5. 統計摘要（處理量、核准率）
6. 規則／名單檢視編輯（如重要聊天室名單）

## 三、這次在 Cowork 執行的任務

優先順序總原則：先求畫面有感，Claude API 放到最後才接——現階段不會產生 API 費用，但基礎建設要做好串接的位置，之後可以直接啟用，不用改造。

### 步驟 1：建立本地端專案資料夾結構 ✅

```
ai-native-agent-hub/
  apps/
    dashboard/          # Next.js 前端（視覺化儀表板）
  agents/
    comm-agent/          # 溝通 Agent（system prompt、規則）
    finance-agent/        # 財務 Agent（未來）
    stock-agent/          # 個人股票 Agent（未來，屬於「個人」範疇）
  supabase/             # 資料庫 schema／設定（先寫好，晚點才連真的 Supabase）
  docs/                 # 規則文件、規格文件（含這份情境說明）
```

### 步驟 2：先做視覺化儀表板（不接 Claude API，用假資料）✅

- 風格：深色 Jarvis 風格 HUD 介面（發光節點、網格背景、掃描線）
- 多代理人節點圖：用 React Flow 呈現代理狀態（閒置／處理中／待核准／異常／未啟用）
- 個人／公司分區：不同顏色系統（公司＝青色、個人＝洋紅），並可切換檢視模式
- 全部使用模擬資料，可用「模擬觸發」按鈕手動改變狀態測試視覺效果
- 內建「新增／串接代理」流程（AddAgentModal），之後新增代理不用改程式碼
- 保留 Claude API 串接位置（`src/lib/ai-client.ts`），目前用假邏輯運作

### 步驟 3：技術串接教學（尚未開始，等畫面確認有感之後）

1. GitHub：建立倉庫、初始化專案、版本控制流程
2. Vercel：部署 Next.js 專案、設定自動部署（push 就上線）
3. Supabase：建立專案、依規劃建表（agent_status、approval_queue、activity_log、config）、設定即時同步

### 步驟 4：Claude API 串接（最後）

確認前面都做起來、整個系統有感之後，才把 `src/lib/ai-client.ts` 的假邏輯換成真正呼叫 Claude API（使用 Haiku 4.5 模型 + 提示快取控制成本），讓溝通 Agent 開始真正處理信件。

## 四、明確的限制與偏好

- 主要溝通語言：繁體中文，簡潔、口語化，不要過度正式
- 現階段不主動串接任何會產生費用的 API
- 個人／公司世界要在資料層面上完全區分，不能混用同一套邏輯
- 每個階段做完要讓使用者實際看到操作、達到成果，不要一次做到底才給他看
